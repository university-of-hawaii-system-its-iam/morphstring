# Python morphString encryption

`morph.py` produces Grouper-compatible encrypted values using Python 3 and
`cryptography`. This project was extracted from the `uh-grouper` repository; 
its original `src/test/docker/morph.sh` remains there as a Java/container 
reference.

From the repository root:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r src/requirements-morph.txt
.venv/bin/python src/morph.py -c
```

This prompts for the key and password without echo and asks for password
confirmation. Like `morph.sh`, the program supports `-k KEY`, `-v VALUE`,
`-c` (decrypt to verify), and `-q` (ciphertext only). The corresponding input
environment variables are `GROUPER_MORPHSTRING_ENCRYPT_KEY` and
`MORPH_RAW_VALUE`; explicit arguments take precedence. Prompts and environment
variables avoid exposing secrets in command arguments. There is no `-g` option
because the program does not run a Grouper image.

Example using only the repository's public test key and a dummy password:

```sh
.venv/bin/python src/morph.py -k je49jwna2jDNcb3 -v letmein7 -c -q
# h6KVnpDwSs9EML2hzZ9SMg==
```

## Reconstructed algorithm

The implementation follows upstream
[Morph.java](https://github.com/Internet2/grouper/blob/GROUPER_6_BRANCH/grouper-misc/grouperClient/src/java/edu/internet2/middleware/morphString/Morph.java)
and
[Crypto.java](https://github.com/Internet2/grouper/blob/GROUPER_6_BRANCH/grouper-misc/grouperClient/src/java/edu/internet2/middleware/morphString/Crypto.java).
It was also checked against the bytecode and outputs of the released
[grouperClient 6.4.1 jar](https://repo.maven.apache.org/maven2/edu/internet2/middleware/grouper/grouperClient/6.4.1/grouperClient-6.4.1.jar).

1. Trim the key using Java `String.trim()` semantics and append the literal `w`.
2. Pad with literal `x` characters to 16 characters when the result is at most
   16 characters, otherwise to 32. Truncate anything longer than 32.
   These lengths count Java UTF-16 code units, before UTF-8 encoding.
3. Encode the resulting key as UTF-8. ASCII keys yield AES-128 or AES-256.
   Non-ASCII keys can produce other byte lengths; invalid AES lengths are rejected.
4. Trim the password using Java `String.trim()` semantics, then encode as UTF-8.
   Trimming removes leading and trailing characters U+0000 through U+0020,
   while preserving non-breaking spaces and other Unicode separators.
5. Apply AES/ECB with PKCS padding (Java calls it PKCS5Padding; for AES this
   is PKCS#7 padding with 16-byte blocks). Java's `Cipher.getInstance("AES")`
   uses this mode/padding with the container's standard provider.
6. Return standard Base64 without line wrapping.

There is no hash-based key derivation, salt, or IV. Output is deterministic.
For ASCII keys of 32 or more characters, only the first 32 affect the result;
the appended `w` is truncated. This also applies to the 48-character keys
generated by `morphkey.sh`.

Inputs are literal strings. Grouper's Java-properties escaping, EL evaluation,
and external key-file lookup are outside this program's scope. UTF-8 matches
the Grouper container; a JVM configured with another default charset may differ.

## Verification

`src/tests/morph-vectors.json` contains 32 vectors generated by invoking the real
`Morph.encrypt()` and `Morph.decrypt()` from the 6.4.1 jar, using a temporary
`morphString.properties` with external file lookup disabled. All keys and
passwords in this fixture are test-only. Cases cover key-length boundaries,
password block boundaries, Java whitespace trimming, and Unicode inputs.

```shell
PYTHONPATH=src .venv/bin/python -B -m unittest discover -s src/tests -p 'test_*.py' -v
```

`src/morph.sh` runs the adjacent `morph.py` and uses the same verification
logic. `-c` compares decrypted output with the Grouper-trimmed password,
accounting for whitespace removed during Grouper-compatible encryption.
The CLI rejects empty and multiline input; the importable `encrypt()` function
also supports the empty trimmed string, as Grouper does. `decrypt()` validates
Base64 strictly and is intended to verify valid encrypted output.

The independent Java comparison harness is also saved in this project. With a
JDK and a local Grouper 6.4.1 client jar, rerun all 63 cases (61 successful
round trips and two invalid-key rejections) with:

```shell
PYTHONPATH=src .venv/bin/python -B src/tests/verify_grouper.py /path/to/grouperClient-6.4.1.jar
```

The harness compiles `src/tests/MorphReference.java` in a temporary directory
and compares real Grouper outputs with Python. It uses only dummy secrets and
does not require the jar or compiled classes to be committed.
